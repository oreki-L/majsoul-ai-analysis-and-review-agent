# 本地模型运行包

普通使用只需浏览器扩展和自己的 LLM 接口。本地模型是可选项：需要时再下载 Windows x64 便携运行包，解压并双击 `start.cmd`，无需自行安装 Node.js、Python 或 Rust。可以不下载任何权重，也可以保留多个模型，一次只运行一个。

本文介绍 v0.15.0 的便携流程。从 v0.14.0 升级请同时更新扩展和本地运行包；旧版预装 Node、手填 Token 的方式见 [旧版说明](https://github.com/oreki-L/majsoul-ai-analysis-and-review-agent/blob/v0.14.0/docs/MODEL_MANAGER.md)。

## 开始使用

1. 单独安装完整 Agent 扩展。需要本地引擎＋LLM 讲解时，先在扩展设置保存自己的 OpenAI 兼容解释服务；只用本地引擎可跳过。
2. 完整解压便携运行包到可写目录，双击 `start.cmd`。启动器使用包内 Node 校验分发文件，再自动打开本机模型管理页。保持运行窗口开启。
3. 选择所需模型并点击“安装”。只有这一步才准备所选权重与必要模型环境；不会顺带安装其他模型。
4. 完成后点击“启动分析”。安装与运行相互独立，启动前会校验资产并检查真实模型推理。
5. 在扩展模型设置选择“本地 mjai”和对应引擎配置，点击“连接本地运行包”，授予本机接口权限；在管理页批准连接。扩展自动填入该模型的分析接口和凭据，无需复制 Token。
6. 连接后分析保持关闭。需要讲解时勾选“本地引擎决策 + LLM 自动解释”，再勾选“开启模型分析”并保存。回牌局授权信息和自家手牌、确认座位，开启“调用模型”，选择“综合攻守”分析。

两个社区 v4 仅用于四人半庄，在模型设置与目录提前说明，不要求每巡勾选。程序继续检查四人局面、事件一致性、授权和合法动作；不自动判断整场是否为半庄。自动分析默认关闭，用户可主动开启原有自家出牌决策点提示。

关闭扩展调用只停止请求。要退出模型，在管理页点击“停止分析服务”或关闭运行窗口。启动运行包、打开管理页或连接扩展，均不会自动安装权重或启动推理；不设置开机自启、系统服务或计划任务。

## 安装、切换与删除

| 模型 | 当前范围 |
| --- | --- |
| Akagi v2 附带的旧 Mortal 弱示例 | 固定旧版示例，用于起步和回归；不是官网 Mortal 4.1 |
| VoidShine/mortal-298k | 社区 Mortal v4，仅四人半庄；作者不推荐排位 |
| Yuchen1457/mortal-582500 | 社区 Mortal v4，本项目仅支持四人半庄；本地未评测牌力 |
| Akagi v3 Native | 第四个独立配置，首期范围为四人半庄；目录验收未完成前不可安装运行，不复用 Mortal 环境 |

支持第四项的扩展和运行包需一同更新；旧版 v0.15.0 发布包不会自动增加 v3。v3 分析地址固定为 `http://127.0.0.1:17345/analyze`，模型管理仍为 `17343`。管理页按目录的真实验证状态开放操作，出现配置项不代表模型已可用。

“安装”只准备所选权重和必要环境。VoidShine 无需先下载 Akagi；两个 v4 共享已验证的固定 CPU 环境，v2 使用独立环境。默认运行包自带管理所需的 Node，不含权重或完整 Python；Python、PyTorch 等由安装流程按需准备。首次安装需要网络，下载／哈希校验失败会显示错误，不换模型或改用 LLM 掩盖失败。

已下载模型可以保留。对另一模型点击“切换并启动”会先停止旧模型，再启动新模型，其他权重保留；在扩展选择对应配置并重新连接后，再自行开启分析。切换配置取消旧在途请求，不把旧建议改标为新模型。

删除前先停止该模型。“删除”只处理管理器拥有且完整性校验通过的该模型目录，不删除共享运行环境、其他模型或用户自备目录。删除后再次使用需要重新下载权重。

## 保存位置与升级

便携启动器默认将权重和模型环境保存在：

```text
%LOCALAPPDATA%\MajsoulAgent\models
  models/{profile}
  runtimes/{runtimeFamily}
```

以后将新版运行包解压到另一个目录，仍会使用同一用户数据目录，复用校验通过的已下载资产。管理页可查看实际位置；不扫描任意文件夹、不自动搬迁或合并旧版包内 `installations/`。

旧用户若要继续使用原目录，可通过高级 CLI 明确指定 `--root`；同样保留所有权、路径及完整性检查。维护者或离线交付可显式导出带固定 Python 归档／wheels 的包，无需预装其他模型。

## 连接与凭据

运行包自动打开管理页时，使用短时、单次启动票据建立本机管理会话；页面清除票据，长期管理 Token 不进入 URL。会话使用 HttpOnly、SameSite=Strict 的非持久 Cookie，服务退出或会话过期即失效，不写入 localStorage 或 sessionStorage。页面刷新可恢复有效会话。

扩展连接需要用户点击，并由管理页明确批准。配对请求绑定扩展来源、随机 nonce、时限及批准时运行的模型；只向该请求一次性交付该模型的分析配置，不交付管理权限。模型切换、服务重启或配对超时后，需要重新连接；迟到响应不能覆盖已切换的草稿。连接本身不保存或启用分析。

自备 mjai 服务仍可在高级配置中手填 `/analyze` 地址和分析 Bearer Token。管理 Token 仅用于管理，不能填写为分析 Token。凭据与 Chat 配置分开保存；本地引擎推理不调用 LLM，开启讲解或追问才发送授权局面到用户配置的 LLM 服务。

## 故障与验证

- 运行包不存在或未启动：先下载、完整解压并运行 `start.cmd`。扩展网页不能直接启动本机程序。
- 校验或安装失败：保留错误状态，按来源与网络检查；目录存在不代表可用。页面没有真实字节进度时显示不确定进度，不估算完成百分比。
- 无法连接：检查运行窗口、所选模型是否已启动、管理页是否批准、接口权限是否授予。配对过期后重新点击连接。
- 端口被占用：先停止原运行包，不自动杀死未知程序或换模型。高级 CLI 改端口时，连接地址也需匹配。

两个 v4 已完成固定真实权重、人工局面与离线管理验收；历史在线试装已通过官方 Python 与全部固定 wheel 下载，但本机 Hugging Face 权重连接失败，完整在线安装尚未通过。新便携启动和免复制连接的本次结果见 [v0.15.0 验收](../VALIDATION.md)，不等于干净 Windows VM、真实整场兼容或牌力认证。[社区 v4 运行说明](MORTAL_V4.md) · [引擎与解释](MJAI.md)

开发者可直接运行 `node agent/model-manager.cjs --toolkit LOCAL_TOOLKIT_DIR --root MANAGED_DIR --port 17343 --open`；目录占位符需替换为实际路径。固定 Node 的来源、哈希和显式维护者准备流程见运行包构建脚本；普通用户无需运行开发命令。
