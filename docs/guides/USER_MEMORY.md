# 整场记忆学习（0.8.0，2026-10-24）

> **使用说明／功能自 v0.8.0 引入。** 下文包含 v0.16.1 的认证座位补充；实时输入与冻结追问关系见[小局会话](AGENT_SESSIONS.md)，规则／事件验证范围见[专项记录](../validation/RULES_EVENTS_VALIDATION.md)。

本功能自 v0.8.0 起包含在完整版中；v0.7.0 安装包不包含。默认关闭，只在用户选择后采集 live 实战中的自家真实动作和授权上下文。牌谱、观看历史、人工复盘均不自动学习为本人。

## 触发与身份

整场完成只认协议 `Hule`、`NoTile`、`LiuJu` 的明确 `gameEnded: true`；普通小局结束只记证据，绝不发起总结。不会用东/南几局、下一次 `NewRound`、最终得分或单次放铳猜整场和习惯。断线/采集解码错误使该整场不可学习；缺开局、事件序号缺口、自家手牌缺失或未知座位使相关小局不可计入可靠覆盖。

门槛是同一整场至少 **3 个可靠、完整结束的小局和 20 个有完整上下文的实际自家动作**。可靠性要求从 `NewRound` 开始、连续事件 `step`、正常结算、完整自家手牌与公开桌面。开关开启前和中途缺失的内容不会补造。未达到门槛只记录 `insufficient`，保留原记忆，不请求模型。

档案仍是浏览器本地 `local-self`，不按账号自动分档。v0.16.1 可从认证请求／响应推导自家座位，仅向桥接层传座位编号；账号、token 和 session 不进入桥接消息或导出。记忆采集接受该 live `Seat` 事件或操作提示 `operation.seat` 作为可信座位来源，人工选择座位不能证明本人身份；仍须满足可靠局面与实际动作门槛。用户只应在本人参与对局时开启；换账号或换实际玩家前须关闭／清除本机档案。不宣称自动区分账户、跨设备同步或识别旁观者身份，没有可靠自家座位来源的局不会提供可学习动作。

## 数据与候选

`user-memory-capture.js` 只在 Agent 入口工作，collector 不加载记忆、Pi、模型接口或额外权限。每个动作保存动作前自家手牌、公开桌面、实际动作、事件位置和观察时间；若当时已有 AI 提示，作为独立 `advice` 字段保存。AI 建议永远不是用户动作或偏好证据。所有快照在 worker 通过 `cleanSnapshot` 再次白名单化，对手暗牌、未来牌谱、账户数据和密钥字段不会进入该合同。

证据、任务、记忆条目是独立集合，位于一个 `agentUserMemoryV1` 原子存储信封中，以便清除/取消和提交保持顺序。最多 8 场证据、每场 32 小局、每局 80 个动作、40 个任务、60 条记忆、24 个小局版本 pin，整体保守预算 3.5MB（按 JSON 字符数 × 3）。超限淘汰旧 pin / 旧证据；过期证据对应任务不会重新请求。字段恢复经过白名单净化，其他 schema 默认不启用；暂时落盘失败保留可重试清理屏障。

整场冻结后以稳定 `memory:<matchId>` 入队，重复结算、重复游标不能重新计数。小局证据 ID 由整场、风、局、本场和动作序号组成。模型仅输出结构化候选；本地验证来源场次、动作引用、条数、长度、样本数、情境分母和行为类型，编造引用、明确偏好、稳定人格标签、无依据概率均不允许自动写档。

候选分为 `observation` 和 `learning-question`，始终显示“待确认候选”。情境目前只支持“已记录自家动作”及“其他玩家已立直时的已记录自家动作”；分母是相应情境下实际记录的动作数，**不是所有合法鸣牌、立直、弃和机会**，不推断未记录的 pass，也不是获胜/放铳概率。候选的引用样本数不能被解释为跨场稳定频率。

首版逐场保留候选，不做语义去重、跨场归并或自动升级稳定倾向；不同场的冲突观察可以并存，90 天后不再提供给工具。用户可修正/确认候选成为明确偏好，也可直接手工添加偏好、删除单条或清除全部。人工编辑立即保存，不等待整场结束。此版不计算伪精确置信度。

## 异步请求、费用和取消

只在学习开启、用户配置的 chat 模型开启、当前接口权限存在且没有实时分析时执行。使用同一自配 API，不新增服务器、向量库、`alarms` 权限或强行保活。浏览器关闭、worker 休眠时不承诺继续或准时运行；下次 worker 启动/消息/实时分析完成是恢复机会。

每场最多一次模型请求，Pi 单轮且无工具；25 秒超时。失败、取消、HTTP 错误、结果不确定均不自动重试，以免重复付费。重启发现已经 `running` 的任务标成 `uncertain`，不能假定没计费并重发。实时分析开始即抢占后台任务。配置变更、关闭学习、修正、删除、清除均使旧任务失效，旧响应不能复活已删除内容。

输入用每小局基线及 JSON Patch 差量压缩，硬上限 **192000 UTF-8 bytes**；Pi 总 token 预算 **196608**，HTTP 输出上限独立为 **2048 tokens**。支持关闭 thinking 的 DeepSeek 接口会为整理任务固定关闭；其他兼容接口使用服务商默认行为，若只返回思考或超出输出上限则安全失败。超出输入预算时任务显示 `budget-exceeded`，不请求模型，不自动拆成多次付费请求。较长整场可能触及输入上限。

合法摸打模拟中的压缩量：3 小局 / 52 个自家动作为 49815 bytes；4 小局 / 70 动作为 66911 bytes；8 小局 / 140 动作为 134013 bytes，明确整场结束后只有一次模拟 HTTP 请求。12 小局 / 210 动作为 200807 bytes，超过预算，零 HTTP 请求。各压缩基线与增量逐个重建都等于原冻结快照。这些规模用例没有鸣牌、杠或立直，不代表所有实战复杂度。

任务单独记录 `lane: memory`、实际调用次数、usage、费用和耗时，不混入 live/manual 运行记录。不提供 usage 或价格时显示未知。界面提供简明状态及原始任务详情。正常模拟整场大小和测试命令见验证证据；这些测试使用 mock transport，不能证明真实服务质量或实战建议质量。

## 小局版本与解释

`NewRound` 消息固定该小局的记忆版本；worker 重启仍沿用已保存 pin。同小局后台总结完成不会改变历史 system 前缀或工具内容。会话隔离键包含 `memoryVersion`，只有 live source、live lane、档案非空时才提供只读 `get_user_memory`；完整档案不会每巡塞进提示词。记忆只能影响解释重点，不能替代当前局面事实、正确牌理或安全校验；候选不是明确偏好。

关闭“整场记忆学习”停止采集与自动总结，已保存记忆仍可用于以后小局的解释；删除单条或“清除所有”才移除相应内容，后者也关闭学习。修正/删除/清除会取消旧会话。可选记忆读取或落盘失败时，实时分析使用无记忆上下文继续。
