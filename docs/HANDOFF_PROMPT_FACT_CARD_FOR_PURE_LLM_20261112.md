## 1. 设计目标与职责

将能够确定的牌名、数量、座位、局况、牌形关系和本地牌效率交给程序计算，LLM 负责选择相关证据、解释和攻守权衡。程序事实不包含对手暗牌、未来事件、实际牌山分布或模型内部思考。

现有混合链路：

```text
授权可见快照及截至当前的事件
  → 快照清洗、冻结、引擎动作校验、本地分析
  → 面向模型统一牌编码 + 中文牌名 + 程序事实卡
  → LLM 解释已确认动作
  → JSON 校验；可修复的格式错误至多修正一次
  → 展示解释；解释失败仍保留 Mortal 已确认动作
```

纯 LLM 可参考的链路：

```text
授权可见快照及截至当前的事件
  → 快照清洗、冻结、本地分析、合法候选
  → 无动作的公共事实卡
  → LLM 自主选牌及解释
  → 程序按当前阶段、实体牌和输出合同校验
  → 可选：为通过校验的建议生成假设弃牌后事实，再核对解释
```

后者是迁移建议，尚未实现。程序计算事实与程序替模型做战略决策是两种职责：向听、进张和安全证据不自动决定进攻、防守或弃和，也不证明某个候选战略最优。

## 3. 输入规范与信任边界

### 3.1 编码统一，中文名称作为冗余校验

面向模型的动作牌码统一为 snapshot 编码，仍保留稳定机器标识；事实卡中的牌描述通常为 `{ code, name, canonical, red }`。

| 牌 | snapshot 编码 | mjai 编码 |
| --- | --- | --- |
| 东、南、西、北 | `1z / 2z / 3z / 4z` | `E / S / W / N` |
| 白、发、中 | `5z / 6z / 7z` | `P / F / C` |
| 赤五万、筒、索 | `0m / 0p / 0s` | `5mr / 5pr / 5sr` |
| 普通数牌 | `1m…9m / 1p…9p / 1s…9s` | 对应普通数牌码 |
| 未知牌 | `?` | `?` |

`forModel` 深拷贝动作数据，只转换模型副本中的 `action/followUp.pai/consumed`，不改原始引擎记录、mjai 传输或合法性校验输入。字段中文化不是把所有牌码替换成自由文本；中文名称帮助阅读，精确牌码负责定位实体与候选。

- 赤五和普通五在实体选择、精确计数、候选行中分开。
- 同种计数和牌形关系将赤五归入普通五，保持同种最多四张的口径。
- `selfHand` 已含已知摸牌，不再追加 `selfDrawnTile`。
- `game.doras` 是宝牌指示牌，程序另给实际宝牌；赤宝身份独立判断，赤宝规则未知时保留限制。

### 3.2 冻结时点与历史

事实卡绑定 `binding.position / source / selfSeat`；当前模型请求、工具查询、建议后的假设状态必须引用同一冻结快照。需要跨请求持久化或缓存时，建议同时记录快照、事实及源码哈希；现有 `binding` 三字段本身不构成内容哈希。

历史建议和教学不等于实际执行记录，更不等于当前事实。现有引擎教学历史带有：

```json
{
  "evidenceRole": "historical-model-advice",
  "currentFacts": false,
  "actionWasExecuted": null
}
```

历史可以承接教学，但可能含错误。冲突时以当前快照和同一时点程序事实为准，不沿用旧局名、旧巡目、旧手牌、旧候选数值和旧安全对象。真实执行必须来自采集事件，而不是从历史建议反推。纯 LLM 历史也应采用同样区分；上述标记目前并非自动应用于所有纯 LLM 路径。

## 4. 事实卡字段与使用口径

以下为逻辑字段索引；字段的完整结构以源码为准。多个子结构有各自状态枚举，不存在一个可用于全部字段的通用 `status` 规则。

| 字段 | 提供内容 | 主要边界 |
| --- | --- | --- |
| `binding` | 事件位置、来源、自家座位 | 绑定时点，不证明动作合法 |
| `tileLegend` | 34种普通牌及赤五的中文与编码对照 | 可以供中文解码，不用于替换精确实体 |
| `currentContext` | 中文局名、自风、本场、自家及逐家巡目 | 缺失为 `null`，不从历史或事件下标补猜 |
| `round / seats` | 场风、庄家、自风、各家相对座位 | 三麻不套四麻自风公式；当前部分三麻风位字段保持未知 |
| `hand` | 当前暗手、精确／同种计数、摸牌、局部牌形、自家已有组合 | 只指自家持有；不能当全场已见 |
| `handTileAvailability` | “牌／已见／未见上界”三列表 | 仅列当前暗手涉及的同种牌，未见不是牌山实剩 |
| `candidateEfficiency` | “弃牌／向听／未见进张上界”三列表 | 弃牌后数值；排序不是引擎偏好，也不是合法候选证明 |
| `localAnalysis` | 现有程序效率及可见计数原始结果 | 规则和信息不完整时不补造数值 |
| `selectedAction` | 当前动作、配套弃牌、弃牌实体、弃后暗手与效率 | 混合链路对应已确认引擎动作；纯 LLM 决策前为空 |
| `actionTransition` | 当前暗手到明确弃牌后的差异 | 无确定弃牌时不模拟后续状态 |
| `situation.players[].melds` | 各家已有组合的中文标签和实体牌 | 只描述当前已有组合，不预测未来鸣牌 |
| `risk` | 逐候选、逐对手的风险依据和安全证据 | 必须同时绑定牌种、对手和时点 |
| `dora / yakuhai` | 指示牌与宝牌、役牌身份及可确认同种组合 | 不代表已验完整役种、振听、番符或得点 |
| `countScopes / limitations` | 各类计数与推断能力的说明 | 约束解释，不要求逐项向玩家复述 |
| `explanationFocus` | 当前动作的紧凑索引 | 不替代完整事实，不是新的分析算法 |

### 4.1 程序局况字段

`currentContext` 主要字段为 `position / roundName / honba / selfWind / selfTurn / turnStatus / turnsBySeat / meaning`。

- 四麻中文局名及自风由当前快照中的场风、庄家座位及自家座位计算。`game.round.index` 在本项目表示庄家座位，不要求模型自行换算局名。
- 巡目仅认可当前快照里 `turnProgress.status=known`、`source=events`、完整合法的逐家数组。
- 巡目的合同是“各家下一次打牌的序号”，不是事件序号；本场数也不是巡目。
- 未知巡目或局名保持 `null`，提示词不要求每次开头复述场况。

### 4.2 可见计数：继续使用三列表

例如某个假设局面的节选：

| 牌 | 已见 | 未见上界 |
| --- | ---: | ---: |
| 南(2z) | 3 | 1 |
| 白(5z) | 4 | 0 |

“已见”包括自家暗手、各家牌河、副露／暗杠、宝牌指示牌，并按本地统计规则对被鸣走的弃牌去重。摸牌不重复追加，杠按四张实体牌计算。未见上界为同种四张减已见数，可能分布在对手暗手、王牌或牌山。

若自家有一张南，打出后自家南从1张变0张，但牌只是从暗手移到牌河，已见仍为3、未见上界仍为1。**自家弃后0张不能解释成全场见尽。**

`handTileAvailability.status`：

| 状态 | 解释方式 |
| --- | --- |
| `complete` | 可引用数值；已见4可称同种牌已全见 |
| `partial` | 可引用已授权范围中的数量与保守上界，必须保留不完整限制，不作全场见尽断言 |
| `invalid / unavailable` | 不推算缺失数值，不输出看似确定的剩余枚数 |

三麻按实际牌种范围处理；本实现会排除二至八万的相关表项和非法计数，但这不代表整个事实卡已完整覆盖三麻规则，当前宝牌和部分风位计算仍有限制。

### 4.3 候选效率：数值必须按同一行读取

`candidateEfficiency.columns` 固定为 `['弃牌','向听','未见进张上界']`。第一列同时给中文和精确牌码，赤五单列。模型按该行读取向听和进张，不允许把最佳候选的数值套给别的候选。

向听取自本地算法；“未见进张上界”不能说成真实牌山进张。声称并列最优须核对全部相关行。这个表既不证明动作合法，也不表示模型必须选效率最好的牌；攻守权衡仍需其他证据。

### 4.4 动作前后差异

`actionTransition` 在有明确弃牌时给出：

```text
status
scope
 discardedTile / drawnTile / discardMethod
 ownTileCount.before / after / scope
 shanten.before / after / change
 isolatedTiles.before / after
 meldsChangedByDiscard
 meaning
```

`status` 为 `available / unavailable / not-applicable`。`discardMethod` 为 `drawn-tile / hand-tile / unknown`；`shanten.change` 为 `improved / unchanged / worsened / unknown`。

- “之前”指当前冻结暗手，已经含摸牌，也可能已经完成鸣牌；不是摸牌前或上一巡。
- 向听不变必须说维持，不能把已完成摸牌带来的改善归因于本次弃牌。
- 弃牌是单张不能证明它刚刚摸入；摸切／手切只读取明确标记。
- 立直只在已有明确 `followUp` 弃牌时生成差异。
- 吃碰杠、缺配套弃牌或弃牌实体不在手中时，不补造后续弃牌。
- 该 helper 本身只做事实构造，不是完整动作合法性验证器。`available` 不等于战略正确，也不能替代阶段、禁打及规则校验。

纯 LLM 决策前没有选定动作，不能提前获得一个被描述为“已执行”的差异。需要差异时，必须把通过校验的建议标为“假设执行此建议后”，并保留它尚未执行的状态。

### 4.5 牌形、孤张和已有组合

`hand.shape` 及弃后 `shape` 提供：

- `sameTileGroups`：对子形、刻子形、四张同种（未宣杠）。
- `possibleSequences` 与 `possibleIncompleteSequences`：可成立的局部组合。
- `incompleteSequenceCompletions`：边张／嵌张／两面和对应补牌及未见上界。
- `isolatedTiles`：暗手中没有同种伙伴，也没有数牌同花色相邻或隔一张联系的全部单张。

局部组合可能共用实体牌，不能相加成完整手牌拆分。孤张不同于单张，孤张也不等于无价值。只有对应集合仅一张，才能说“唯一孤张”。未知牌、非法牌或同种超过四张时，`shape` 为 `null`，不能声称已完整枚举。

已有组合同时验证类型和实体牌形：type0为三张合法顺子时称明顺子；type1为三张同种时称明刻；type2为四张同种时称明杠；type3为四张同种时称暗杠。否则 `label=null / status=unavailable / visibility=unknown`。暗杠是四张，不能说暗刻；暗手里有三张同种也不代表最终和牌一定按刻子拆分。

### 4.6 安全证据绑定对应玩家

`risk.candidates[].opponents[].safety` 给 `status=confirmed/unknown`、证据数组与适用范围。证据类型包括：

- `river`：对应对手本人的牌河。
- `riichi-passed`：依据立直声明、他家弃牌及之后继续进行的授权事件，核实立直后通过；当前还在等待响应的弃牌不直接算已通过。
- `visible-exclusion`：四麻、完整合法可见统计下，同时排除同种等待、涉及的顺子与适用的国士等待；不能简化成“已见四张所以必安全”。

`genbutsu=false` 仅表示本人牌河没找到，不能推出危险；`unknown` 表示缺少确认依据。对某家确认安全不能推给其他家，也不能推给未来。筋和壁不保证安全，不生成虚构放铳概率。

现有纯 LLM `analysis.js` 的 `safe` 输出校验仍只接受本地 `genbutsu=true` 的对应对手。若希望使用新增安全证据，需要同步调整数据接口与结果校验；不能只修改提示词而让它输出现有解析器不接受的标签。

## 5. 控制输入复杂度

用户已明确偏好精简表格。当前保留两个三列表；新状态差异用紧凑对象表达，不再把各类计数塞进一张多列表。

`explanationFocus` 是当前动作索引，保留局况、组合概览、选定弃牌的局部关系、效率与逐对手安全，并以 `candidateEfficiencySource / actionTransitionSource / meldsSource` 指向事实卡对应字段，减少再次复制完整新表。提示词要求选一至三条相关依据，不复述整张卡。

事实卡仍保留图例牌、原始本地分析等冗余字段，现阶段没有证据证明当前字段量是最优。纯 LLM 可以设计瘦身投影或按需工具读取，但必须保留状态、数量口径、精确实体牌与时点，不能只剩一串失去语义的数字。

当前 `compare_discards` 读取本地效率，`get_danger_evidence` 在混合链路读取增强后的 `risk`。已附同一冻结状态的计算可直接引用，无需为了使用工具而重复查询；缺项或有疑义时再查询。

## 6. 提示词的组织与迁移

当前解释系统提示词按以下顺序组织：角色和动作权限 → 编码和座位 → 当前事实与历史 → 动作阶段 → 自主决定是否比较备选 → 事实卡读取 → 局况、效率、状态差异、牌形、计数和风险边界 → 简短中文与严格 JSON。

纯 LLM 建议保留共同规则，替换角色、决策权限和输出合同：

| 可复用内容 | 纯 LLM 适配点 |
| --- | --- |
| 牌名、编码、赤五与未知值规则 | 原样保留语义，按实际输入字段名调整 |
| 当前事实优先、历史不是执行记录 | 应用于纯 LLM 自己的历史建议 |
| 局况、计数、牌形、安全事实 | 接入公共事实卡与工具，别只加提示文字 |
| 模型自主决定是否比较备选 | 移除冲突的旧分支指令；没有教学价值时不强制比较 |
| 不编造概率、役种、牌山和理由 | 保留；证据不足时允许策略未知或降低结论强度 |
| 引擎动作不可更换、不能输出动作字段 | 这是混合链路专用。纯 LLM 需要自主决策，不能照搬 |
| “依据不足以解释引擎取舍” | 改为“当前安全／打点证据不足，无法确定攻守取舍”等与自主决策相符的表述 |
| `summary/reasons/limitations` 解释合同 | 纯 LLM 保留自己的决策 Schema 与校验，不能直接使用 `E.parse` |

**当前存在的冲突点：**`agent.js` 的纯 LLM `live-ned` 非 danger 分支仍追加“多个合法候选至少比较一个实质备选”的指令；这与本轮用户确定的自主比较设计不同。本文只记录迁移要求，本轮没有改动该分支。

现有纯 LLM 输出顶层为 `task / danger / efficiency / decision / limitations`，`decision.action` 为 `attack / defend / fold / unknown`，`decision.tile` 是建议弃牌。这个合同不能直接表达完整的吃碰杠立直动作选择；若扩展决策范围，必须另行扩展合同、合法动作来源与校验，不能靠解释文字伪装已支持。

建议的公共指令片段（设计建议，未接入或实测；输出合同另由当前任务注入）：

```text
你根据当前授权的冻结快照、程序事实和合法候选进行决策。程序提供可核查事实，你负责选择与解释攻守取舍；效率排序不等于战略最优。
牌名、局名、自风、巡目和数值直接读取当前事实。未知不补猜，历史模型建议可能有错，也不代表已经执行。
已见包含自家暗手，未见是上界；自家弃后0张不等于全场见尽。局部组合可能重叠，唯一孤张须以完整集合为准。
风险按对手、牌种和当前时点分别判断。确认安全只适用于证据对应的对手；缺少安全证据不等于危险。不要编造概率、完整役种或牌山实剩。
由你根据问题和教学价值决定是否比较备选，即使有多个合法候选也不强制列出备选。用户明确要求比较时回应所问。
区分已核实事实与推测。安全或打点证据不足时说明限制，不用虚构理由证明选择正确。
只输出当前任务指定的JSON结构，建议牌必须满足当前合法候选约束；没有合法建议时按合同返回未知或null。
```

## 7. 纯 LLM 接入建议

先复用公共事实，不要求引入 Mortal。以下仅为接口示意：

```js
const Facts = require('../extension/engine-facts.js');

// snapshot 必须已经清洗、冻结；localAnalysis 必须来自同一快照。
// events 必须限制在当前授权时点及可见范围。
const facts = Facts.buildFactCard(snapshot, {}, localAnalysis, { events });
```

无动作时仍可获得公共局况、手牌、计数、效率、已有组合和风险；`selectedAction` 没有选定动作、`actionTransition` 不适用、`explanationFocus.discard=null`。纯 LLM 初次输入优先采用公共字段；不要把空的动作索引伪装成引擎建议。

随后将公共事实作为明确标记“仅作数据”的消息注入现有纯 LLM 请求，保留当前动态合法候选及输出合同。若需要建议后状态，在模型输出经过本地合法性校验之后，将已经转换为 snapshot 编码的动作传入 `buildFactCard`，并在外层标为模型建议的假设状态。不要直接把 `decision.action='attack'` 当成 mjai 动作类型，弃牌应另映射为 `dahai`。

不要为了引入这些事实默认增加第二次付费调用；是否用额外解释轮次应由效果和成本决定。单轮可以先用候选效率及公共牌形事实决策，再在本地检查解释中的具体断言。

## 8. 结构化输出与修正

当前混合链路合同：

```json
{"summary":"简短解释","reasons":["可核查的依据或取舍"],"limitations":[]}
```

三个字段必须全部出现；数组无内容用 `[]`，不能省略、用 `null` 或字符串代替。`summary` 为非空字符串，最多1000字符；两个数组各最多8项，每项为非空字符串且最多1000字符。不接收额外字段、Markdown或JSON之外文本。

可修复的 JSON／类型错误允许一次格式修正；当前解析器把额外动作等字段视为合同违规，直接拒绝，不作为普通格式修正接受。失败不能通过默默丢字段变成成功，也不能因此重跑 Mortal。纯 LLM 若采用相似修正流程，须使用自己的 Schema 和校验器，格式修正不授权绕过非法动作校验。
