# 实时分析：历史事实与确定性比较

v0.13.0 在完整四麻的实时自动综合分析中采用 X-F。它在原 X-S 的当前完整授权状态、原 N/E/D 计算、重要事件与代码压缩旧事实之上，追加阶段三原版确定性事实目录；不发送旧模型意见。重要事件与本地计算在旧 NED 中已经存在。

## 模型收到的内容

- 当前完整授权局面：自家手牌、已授权桌面与有序牌河，不从历史补回当前未授权信息。
- 原导航与计算：座位/局风/自风/宝牌说明，向听、进张未见枚数上界，以及逐家现物、筋、壁和对应来源。
- 已采集的重要事件：开局事实、立直与副露，以及从已观察状态确定的宝牌、分数/立直棒变化；不补造中间动作。
- 全部已采集旧状态的代码压缩事实：按路径和值建立类型化字典，保留每个来源时点和显式空值；它们是历史，不能覆盖当前 snapshot。
- 当前确定性比较目录：包括合法候选、并列最低向听与同向听最大进张上界、精确弃牌后的手牌/赤牌数、逐候选逐对手现物状态。未知牌河对应现物为 null，不把无证据说成安全。

这不是由另一个模型生成的摘要，不增加摘要模型请求、强制 `factClaims` 或二次纠错，也不自动执行游戏动作。目录中的 ID/哈希用于绑定来源，不证明自然语言理由或策略正确。最终五字段 JSON 仍经过原严格校验。

## 适用范围与回退

只有自动实时 Chat、问题为空、非独立决策讨论、四人麻将、四家授权牌河、已授权手牌、有效非负事件位置，以及本地允许弃牌的 `combined` 任务使用 X-F。危险牌/牌效率任务、三麻或其他不满足条件的自动请求继续使用原 NED；手动分析、普通复盘和冻结决策追问保持完整上下文合同。此发布不扩大专业引擎或游戏操作资格支持。

旧事实来自原有小局存储的授权基线和全部观察增量。界面最近8个导航检查点不裁剪送入压缩器的事实；未采集的早期状态仍然未知。本地2MB及事件/问答安全上限保持，达到上限会拒绝继续，而不是静默丢弃旧事实。授权、身份、模型或配置变化继续隔离会话；提示版本升为7，不接续旧策略的自动上下文。已保存的独立决策讨论仍可回看。

产品保持实时最多2次模型请求、4次工具调用、25秒（思考模式120秒），手动最多3次模型请求。历史更多意味着请求可能更大，不承诺缓存、费用或速度改善。用户自配 API、权限选择、直接请求所选服务、未知费用处理与六个只读工具继续沿原边界；可选用户记忆仍通过固定版本工具读取。

## 安装与回退

从 [v0.13.0 Release](https://github.com/oreki-L/majsoul-ai-analysis-and-review-agent/releases/tag/v0.13.0) 下载完整版 ZIP 和 SHA256SUMS，核对后解压。在 Chrome/Edge 扩展管理页使用“加载已解压的扩展程序”，选择直接包含 manifest.json 的目录；已加载开发目录可替换为新版目录后刷新扩展。仅获取器 ZIP 不包含 X-F 或任何模型代码，不要同时启用两种配置。

保留原解压目录与数据导出。若需回退，停用新版并重新加载 [v0.12.0](https://github.com/oreki-L/majsoul-ai-analysis-and-review-agent/releases/tag/v0.12.0) 完整版，保持原授权与模型配置；替换安装目录可能产生不同的扩展 ID，应先导出需要保留的记录和配置。不要在两版之间复制整份浏览器配置或密钥文件。回退不改写旧发布 tag 或资产。

## 验证边界

纯构造器对四个冻结 X-F run 的45个首答 system/message内容和顺序逐条等价通过，包含事实目录和哈希。这证明同一已绑定输入的构造一致性；真实产品使用自己的会话标识、已采集历史、原有任务/合法性条件和更短预算，因此不等同于产品在线复测。没有调用新模型 API 或重跑基准。
